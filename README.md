# 浅草健身计划

网页：<https://kyoushingi-lab.github.io/asakusa-fitness-plan/>

已启用本地日期重量历史和 Supabase 跨设备同步。未登录时保存到本机；手机、电脑分别通过同一个邮箱登录后，自动合并日期和重量。

周一、周三、周五训练计划，9 种器械的实物参考图与视频，15 张可展开说明卡，训练打卡、日期重量历史、备份导入导出、30 分钟爬坡计时和饮食建议。

## 当前训练安排（2026-10-20 更新）

目标是臀部稍微丰满、圆润，腿部以维持为主。周三先做臀部训练机；周五将腿举改为髋外展。每周合计：臀部训练机 6 组、髋外展 4 组、腿举 2 组、卧姿腿弯举 2 组。各动作次数见网页。

周一训练和饮食建议沿用原计划；周一、周五爬坡 30 分钟，周三轻松走 10～15 分钟。先观察 8～12 周的臀围、大腿围、腰围和侧面照片。训练侧重不保证大腿围不变。

周五髋外展使用独立打卡项，并与周三共用髋外展的最近重量。旧腿举历史继续保留在“我的重量记录”中。

## 使用

用 Safari 或 Chrome 打开网页。填写重量后停顿 1 秒，或离开输入框，会自动保存填写时的本地日期、时间、器械和公斤数。刷新前的未完成输入也会保留为草稿。相同器械同一天连续填写相同重量不重复记录；不同重量会追加记录。已有默认重量不会自动变成训练记录。

未登录时保存在当前浏览器。登录同步账号后，同一邮箱的设备会自动合并重量历史，联网时约每 30 秒同步，也可点“立即同步”。训练打卡和计时器仅在本机使用。历史不会提交进本仓库。退出账号不会删除本机缓存。

“导出备份”生成可重新导入的 JSON；CSV 可用表格软件查看。更换网址时浏览器不会自动搬迁本地数据，需要从旧网址导出并在新网址导入。旧版网页没有日期历史，不能恢复从未记录过的日期。

## 继续更新

本仓库直接发布静态文件，无需构建：

- `index.html`：训练内容与页面结构。
- `styles.css`：手机与电脑布局。
- `app.js`：计时、记录、备份和同步逻辑。
- `assets/`：器械参考图；来源见 `MEDIA-SOURCES.md`。
- `vendor/supabase.js`：Supabase JavaScript 客户端 2.118.0。
- `cloud-config.js`：项目 URL 和允许公开的浏览器密钥。不要放服务端密钥或数据库密码。
- `supabase/schema.sql`：重量表和按账号隔离的访问策略。

GitHub Pages 使用 `main` 分支的根目录。更新这些文件并提交到 `main` 后，GitHub Pages 会重新发布。

数据库只允许已登录账号读取与追加自己的记录；未登录访客不能读取重量表。记录采用追加与合并方式，不提供覆盖整份云端历史的操作，避免离线设备覆盖另一台设备的数据。

## 验证与同步配置

安装测试依赖后，运行 `npx playwright install webkit chromium`，再运行 `npm run test:webkit` 或 `npm run test:chromium`。测试使用隔离的浏览器环境，不会读取个人浏览器记录；同步测试使用真实客户端与模拟服务，不会发送真实登录邮件。

现有 Supabase 项目已建立重量表并启用按账号隔离的访问策略，不必重复执行建表 SQL。`supabase/schema.sql` 用于新项目初始化，`supabase/verify-rls.sql` 验证不同账号与未登录访问隔离，其测试账号和记录会在事务中回滚。网页只填写允许公开的 publishable key，不能填写 secret key、service_role key 或数据库密码。

2026-10-20 使用独立临时账号、真实登录会话和真实数据库 API，通过 7 项场景：电脑上传及手机模式读取、断网补传、重复记录处理、跨账号与匿名访问隔离、禁止覆盖和删除历史、刷新恢复登录记录。真实邮箱链接投递和 iPhone 真机尚待用户验证；这些测试没有发送邮件。

免费服务的默认登录邮件提供一次性登录链接。将 Supabase 的 Site URL 设为本网页完整地址，手机和电脑分别通过同一个邮箱的登录链接进入网页。默认邮件服务只适合项目所有者／团队成员的邮箱；扩大到其他使用者需单独配置邮件服务。
