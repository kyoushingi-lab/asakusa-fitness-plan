# 浅草健身计划

网页：<https://kyoushingi-lab.github.io/asakusa-fitness-plan/>

已启用本地日期重量历史和 Supabase 跨设备同步。未登录时保存到本机；手机、电脑分别通过同一个邮箱登录后，自动合并日期和重量。

灵活 A→B→C 循环训练，9 种器械的实物参考图与视频，15 张可展开说明卡，忙碌日标记、训练打卡、日期重量历史、备份导入导出、30 分钟爬坡计时、体态维护和饮食建议。

## 训练安排与页面操作

主目标是薄肌感和背部训练，臀腿作为搭配安排。A练背、手臂和腹，B练臀腿和腹，C练背和臀。每周2次或3次都可以，按 A→B→C 接着练，不在周初重置。A、C后爬坡30分钟，B后轻松走10–15分钟。各动作组数与次数见网页；前1–2周按新手提示减少组数，三头肌易疲劳时从1–2组×10–12开始。

训练面板显示A/B/C进度和周历。选择实际训练日期和项目，点“记录…已完成”；支持补记过去日期，未来日期不能预记为完成。今天已有A时，仍提供“为B选择训练日期”的入口，点击只打开日期选择，不会覆盖A；B训练当天打开即可记录B。

更正已有日期需先点“更正这天的记录”。可删除该日期的循环记录，并在当前页面撤销上一步操作。补记旧日期不会把下一次推荐倒退；下一次以时间上最新的训练为准。旧版A记录和忙碌日原样读取。同肌群尽量隔约48小时；器械占用可跳过。日常轻量体态维护5–8分钟，完整20分钟视频仅每周1–2次，安排在非臀腿训练日。

C的髋外展与B共用最近重量，器械打卡分别记录。保留旧存储键和旧重量历史。循环、忙碌日、器械与体态打卡仅存本机，重量历史沿用已有账号同步；JSON/CSV备份仍导出重量，不包含循环和打卡。

所有器械说明与体态动作在HTML中完整提供，原生details默认展开。关闭JavaScript仍能阅读并展开照片；脚本受限时计时和自动记录不可用，控件会保持禁用并显示说明。B站视频是用户提供的外部链接，未验证其内容版本与完整播放。

## 使用

用 Safari 或 Chrome 打开网页。填写重量后停顿 1 秒，或离开输入框，会自动保存填写时的本地日期、时间、器械和公斤数。刷新前的未完成输入也会保留为草稿。相同器械同一天连续填写相同重量不重复记录；不同重量会追加记录。已有默认重量不会自动变成训练记录。

未登录时保存在当前浏览器。登录同步账号后，同一邮箱的设备会自动合并重量历史，联网时约每 30 秒同步，也可点“立即同步”。训练打卡和计时器仅在本机使用。历史不会提交进本仓库。退出账号不会删除本机缓存。

“导出备份”生成可重新导入的 JSON；CSV 可用表格软件查看。更换网址时浏览器不会自动搬迁本地数据，需要从旧网址导出并在新网址导入。旧版网页没有日期历史，不能恢复从未记录过的日期。

## 继续更新

本仓库直接发布静态文件，无需构建：

- `index.html`：训练内容与页面结构。
- `styles.css`：手机与电脑布局。
- `app.js`：计时、记录、备份和同步逻辑。
- `assets/`：器械参考图；来源见 `MEDIA-SOURCES.md`。
- `vendor/supabase.js`：Supabase JavaScript 客户端 2.118.0。
- `cloud-config.js`：项目 URL 和允许公开的浏览器密钥。不要放服务端密钥或数据库密码。
- `supabase/schema.sql`：重量表和按账号隔离的访问策略。

GitHub Pages 使用 `main` 分支的根目录。更新这些文件并提交到 `main` 后，GitHub Pages 会重新发布。

数据库只允许已登录账号读取与追加自己的记录；未登录访客不能读取重量表。记录采用追加与合并方式，不提供覆盖整份云端历史的操作，避免离线设备覆盖另一台设备的数据。

## 器械档案与计时

器械详情分别展示固定档位和上次记录重量。臀部机已确认 Hammer Strength Select Hip & Glute（HS-HG）；腹肌机确认 Life Fitness 品牌，具体型号未核实。其余整机照片明确标为参考机型。新增10张用户提供的调节位置实拍，使用原生 details 默认收起，关闭脚本仍可展开。腹肌机错误整机参考图已移除，当前显示高度调节特写，完整外观照待补充。

训练循环与日历默认收起，摘要保留下一次训练项目。爬坡计时放大坡度与速度，每段之间增加10秒调参，30分钟训练加4次间歇共30分40秒，暂停、继续和后台时间校正保留。

“我的重量记录”内可展开“导入个人训练档案”。个人档案文件不提交到仓库；导入合并重量历史并校正指定日期的训练，其余日期保留。没有训练时间的历史使用 `date-only:` 稳定ID，数据库中的午夜时间仅用作排序锚点；页面显示“时间未记录”，CSV时间留空。登录后重量自动同步，日历、动作完成情况仍保存在本机。

`npm run build:offline` 生成仓库外的完整单文件HTML，内嵌图片和文字，关闭脚本仍可阅读及展开照片。离线文件数据与在线网址分开保存；同步请使用在线网页。

## 验证与同步配置

网站版 WebKit 与 Chromium 手机模式各34项基础交互测试通过。升级专项含折叠日历、私人档案合并、日期与跳过动作保留、重复导入、未知时间、无脚本展开、4次调参间歇及手机布局。同步测试含日期未知时间记录的自动上传与另一设备读取。未做iPhone真机测试。

安装测试依赖后，运行 `npx playwright install webkit chromium`，再运行 `npm run test:webkit` 或 `npm run test:chromium`。测试使用隔离的浏览器环境，不会读取个人浏览器记录；同步测试使用真实客户端与模拟服务，不会发送真实登录邮件。

现有 Supabase 项目已建立重量表并启用按账号隔离的访问策略，不必重复执行建表 SQL。`supabase/schema.sql` 用于新项目初始化，`supabase/verify-rls.sql` 验证不同账号与未登录访问隔离，其测试账号和记录会在事务中回滚。网页只填写允许公开的 publishable key，不能填写 secret key、service_role key 或数据库密码。

此前使用独立临时账号和真实数据库 API，验证上传、下载、断网补传、重复记录处理、跨账号与匿名访问隔离、禁止覆盖和删除历史、刷新恢复登录记录。真实邮箱链接投递和 iPhone 真机尚待用户验证；这些测试没有发送邮件。

免费服务的默认登录邮件提供一次性登录链接。将 Supabase 的 Site URL 设为本网页完整地址，手机和电脑分别通过同一个邮箱的登录链接进入网页。默认邮件服务只适合项目所有者／团队成员的邮箱；扩大到其他使用者需单独配置邮件服务。
